# Load Testing — Shrinkr

This directory contains a [Locust](https://locust.io/) load testing suite for the Shrinkr backend.

---

## Prerequisites

```bash
# From backend/ directory:
pip install -r requirements-dev.txt
```

---

## Authenticated Load Testing Setup

To test authenticated endpoints safely without modifying production authentication or email/OTP verification rules:

1. **Create a dedicated load test account once** (e.g. via `/auth/register` or the app UI).
2. **Verify its email/OTP once** so the account is active.
3. **Pass credentials to Locust via environment variables** (do NOT commit secrets to git).

### PowerShell (Windows)
```powershell
$env:LOAD_TEST_EMAIL="loadtest@example.com"
$env:LOAD_TEST_PASSWORD="your-test-password"
```

### Bash / Linux / macOS
```bash
export LOAD_TEST_EMAIL="loadtest@example.com"
export LOAD_TEST_PASSWORD="your-test-password"
```

## Quick Start

**1. Start the backend** (if not already running):
```bash
# Docker Compose:
docker compose up

# or locally:
uvicorn app.main:app --reload --port 8000
```

**2. Run Locust with web UI:**
```bash
locust -f tests/load_testing/locustfile.py --host http://localhost:8000
```

Then open **http://localhost:8089** in your browser.

- Set **Number of users**: `10`
- Set **Ramp-up rate**: `2` users/second
- Click **Start swarming**

## Headless / CI Mode

```bash
# 50 concurrent users, spawn 5/s, run for 30 seconds, output CSV:
locust -f tests/load_testing/locustfile.py \
    --host http://localhost:8000 \
    --headless -u 50 -r 5 -t 30s \
    --csv=tests/load_testing/results/report

# Results are written to:
#   tests/load_testing/results/report_stats.csv
#   tests/load_testing/results/report_failures.csv
#   tests/load_testing/results/report_history.csv
```

## Status Codes & Expected Behavior

Locust has been configured with custom `catch_response=True` handlers to distinguish between legitimate application behavior and actual server failures:

- **Redirects (`/{short_code}`)**: Returns HTTP `307 Temporary Redirect` (or `301`/`302`). Marked as **SUCCESS**.
- **Shorten (`/shorten`)**: Returns `200 OK` or `201 Created`. Marked as **SUCCESS**.
- **Rate Limit (`429 Too Many Requests`)**: Occurs when rate limiters trigger under high volume. Marked as **SUCCESS** (rate-limiter working as intended).
- **Server Errors (`500 Internal Server Error`)**: Marked as **FAILURE** (indicates server collapse or unhandled exceptions under load).

## User Profiles & Task Weights

| User class | Weight | Description |
|---|---|---|
| `AnonymousUser` | 3 | Clicks short links, occasionally shortens a URL anonymously |
| `AuthenticatedUser` | 1 | Uses pre-verified credentials to shorten links and view analytics |

### `AnonymousUser` tasks

| Task | Relative weight | Endpoint |
|---|---|---|
| `follow_redirect` | 10 | `GET /{short_code}` (307 redirect) |
| `health_check` | 2 | `GET /health` |
| `shorten_anonymous` | 1 | `POST /shorten` |

### `AuthenticatedUser` tasks

| Task | Relative weight | Endpoint |
|---|---|---|
| `list_my_links` | 8 | `GET /my-links` |
| `shorten_authenticated` | 5 | `POST /shorten` |
| `view_analytics` | 3 | `GET /analytics/{code}` |
| `view_timeseries` | 2 | `GET /analytics/{code}/timeseries` |
| `view_my_stats` | 1 | `GET /auth/my-stats` |

## Interpreting Performance Metrics

| Metric | Good target | Investigate when |
|---|---|---|
| p50 response time | < 50 ms | > 200 ms |
| p95 response time | < 200 ms | > 1 000 ms |
| p99 response time | < 500 ms | > 2 000 ms |
| Server 500 Error rate | 0 % | > 0.1 % |
| RPS throughput | — | Drops under sustained load |
